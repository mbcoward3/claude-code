Today the review page binds 127.0.0.1 inside the session's container, so in Claude Code on the web the reviewer can never reach it and the skill silently falls back to a markdown wall. This plan makes the interactive review reachable from any session type while keeping the local-CLI path exactly as it is.

Approach

  1. Environment detection Add a detect subcommand to plan_review_server.py that classifies the session as local or remote by checking for the remote-container sentinel env vars and whether a real browser can plausibly reach the bind address. SKILL.md branches on its output. An explicit PLAN_REVIEW_MODE=local|remote env var overrides detection for tunneled or otherwise unusual setups.
  2. Remote transport Implement the signed relay URL transport (below) behind the same serve / wait / stop interface so SKILL.md stays transport-agnostic.
  3. Snapshot export Add export --dir DIR --out FILE that inlines the current plan into app.html as a single static file, with annotations posted back by pasting a compact JSON blob into chat. This is the universal fallback when no transport works.
  4. Docs + tests Update SKILL.md, README.md limitations, and add a tests/test_server.py covering detect, serve idempotency, submit, wait, and export.

Remote transport

Serve through the platform's preview-URL relay when one exists (e.g. a proxied https://…preview… hostname), with a per-round signed token in a query parameter — sent to the server on every request, so auth is enforced from the first page load — to keep the page private.

Pros

  • One-click for the reviewer, works on mobile

Cons

  • Platform-specific; needs a token/auth story
  • Bigger blast radius if the token leaks
Main risk: any transport that leaves loopback turns an unauthenticated page into a network service. Every remote mode must require the signed token before rendering the plan or accepting POST /api/submit.

Out of scope / future work

Multi-reviewer sessions, persisting review history beyond the state dir, and a hosted relay service are all explicitly out of scope for this pass. The export-file flow deliberately has no way to submit feedback programmatically; pasting JSON into chat is acceptable for the fallback tier.

Local CLI sessions see zero behavior change — same URL, same flow, same files on disk.
